# 花（Hua）

一个**给自己用**的桌面小工具：记录每天要做的事、做完的事、做完之后的心得，以及每天睡了多久。

纯本地、单人使用 —— 没有账号、没有同步、没有任何联网行为。数据就是一个 SQLite 文件加几个 Markdown，
放在你自己的磁盘上，拷走就是备份。

界面是双主干：左边「今日事项」，右边「今日记录」。重心是**记录与回顾**，不是催促你干活。

## 日志

侧栏「日志」页：**一天一篇**，像日记本，不再是「一天多条」的碎片列表。

左栏是日期列表（近 30 / 90 / 365 天里有内容的天 + 今天），中间是一整片编辑区——一个标题、一篇正文，写完整篇自动保存。今天写的所有内容自然连成一整篇。

**右栏是那天的完成事项**，和正文并排、各自独立滚动。放在正文下面的话，日志一写长就沉到屏幕外了；并排之后回顾时「写的」和「干的」能同时看到。窄屏（< 900px）自动收成上下堆叠。

- 「固定到今日页」把某一天的日志钉在今日页右栏，跟固定事项并列。
- **左栏除了日期，还显示那天日纪的标题**（没标题显示「（无标题）」，没写显示「还没写」）——
  光看日期想不起来那天写了什么。
- **「最后改于 10/17 12:20」**：主栏标题旁显示，日历视图点开某天的预览里也有。
  这个时间不来自磁盘（周文件里没存），存在 `journal_index.updated_at` 里；
  索引每次保存都会重建，重建时按 `date|time` 把时间认领回来，所以不会丢。
- 「清空这一天」只清这一天的日志正文和标题，同一天的完成清单不受影响。
- 今日页右下角只留一个入口和一段摘要——正文在日志页里，今日页不再承载写作。
- **日期一律按日界算**（默认凌晨 4 点前算前一天）。凌晨 1 点写的那篇属于「还没睡的那一天」，
  不会被劈到次日去。日界由主进程统一算好下发，页面不自己取系统日期。

**磁盘格式没有变。** 日志仍然落在周文件的 `### 心得` 下，一天一篇在存储上就是这一天只有一条 `#### HH:MM`。旧的「一天多条」数据会自动聚合：各条按时间顺序首尾相接成一篇，原本各条的标题降级成正文里的 `### 小标题`（这样「这段是为什么写的」不会凭空消失），时间沿用当天最早一条，任意一条置顶则整篇置顶。写完再打开，一天多条会被合并成一条——**合并前请确认**，这是单向的。

## 界面大小

设置页「界面大小」：标准 / 大 / 更大 / 很大（100 / 115 / 130 / 150%），也可以用
`Ctrl + +`、`Ctrl + −`、`Ctrl + 0`，或 `Ctrl + 滚轮`（80%–200%）。

用的是 `zoomFactor` 整体缩放，不是只调字号——文字、间距、按钮一起变，比例才协调。
值存在 `meta` 表的 `zoom` 键里，下次打开还是这个大小。

内容本身是按窄栏排的（日志正文 900px），所以屏幕越大、全屏之后越显得小——用这个放大合适。

## 睡眠

侧栏「睡眠」页：只填**入睡**和**起床**两个时间点，时长和分档都是算出来的（跨午夜会自动处理）。
时间框旁边有 ± 半小时的微调按钮，改完不用重新点开选择器。

**日期怎么算的**：记录存的是**醒来那天**（16 晚 → 17 晨 存在 17 号），因为「昨晚睡得怎么样」
是早上打开时问的问题。但页面上不会只写「10 月 17 日」——那样容易被读成「17 号晚上」，
所以统一显示成 **「10/16 晚 → 10/17 晨」** 这一段。页头、柱子提示、今日页的睡眠卡都是这个写法。

下面是近 14 / 30 / 90 天的柱状图：柱子按档位着色，站在一条基线上；6h / 9h 两条极淡的网格线标出
正常区间的边界，一条 7h 虚线是建议下限（**虚线的含义写在图下面**，因为任何高于 7 小时的柱子都会
顶到线上方，标签放哪儿都会压住一根柱子）。**点柱子可以回看那一天**的明细。

> 图上不画趋势折线，也不画 7–9 小时的背景带 —— 柱子本身已经表达了走势，再叠一层只会糊成一团。

再下面是**一行关键数字**（平均时长 / 正常率 / 作息规律度 / 有记录的天数），用细竖线分隔，
不是六张各自为政的小卡片。中位数、最长最短、波动、平均入睡起床这些细节收进「更多数据」，
默认不展开 —— 一屏里不需要同时看八个数字。

分档分布是一条**堆叠条**加一行图例（带每档天数），它同时充当柱状图的图例，所以图上不再单独放一排色块。

- 平均时长、中位数（一半的天比它长）、时长波动（标准差，越小越稳）
- 正常率、不足 6 小时天数
- 平均入睡 → 平均起床
- 作息规律度：把入睡时刻的离散度折算成 0–100 分，附上 ±多少分钟
- 分档分布：四档各占多少天，用横条画出来
- 30 天跨度下会跟「上一段 30 天」对比平均时长与正常率

若该段时间有缺记录，会明确提示「还有 N 天没记」——缺得多的时候，上面的均值只代表记了的那些天。

分档按睡眠时长，四档配色：

| 时长 | 判定 | 颜色 |
|---|---|---|
| 不足 6 小时 | 严重不足 | 红（`--danger`） |
| 6–7 小时 | 偏少 | 琥珀（`--warn`） |
| 7–9 小时 | 正常 | 绿（`--ok`） |
| 9 小时以上 | 偏多 | 灰（`--text-3`） |

依据是「健康成年人每晚至少 7 小时」（Sleep Foundation / 美国国家睡眠基金会指南，
核对日期 2026-09-22，以官网为准）。阈值只写在 `electron/sleep.cjs` 一处，随 bootstrap 下发到界面，
前端不重复定义常量。这里只做记录和汇总，**不构成医学建议**。

「生成分析报告」会把 Markdown 落到 `reports/sleep-<起>_<止>.md`，**同时把正文直接显示在当前页面上**——
点完按钮总要看到点什么，只 flash 一句「已生成」会让人以为没反应。报告里除了原有内容，
也会带上中位数、波动和作息规律度。

> 报告正文用的是列表而不是 Markdown 表格：应用自带的转换器（`src/md.js`）不支持表格，
> 硬写表格会原样显示成一堆竖线。列表在记事本里也一样好读。

## 今日页

界面是双主干：左边「今日事项」，右边「今日记录」。**但最上面那条录入框才是主角** ——
它横跨整页、字号更大、聚焦时整张卡描边，因为「记一件事」是这个应用最核心的动作。

录入框的设计是「**一条可以写的线 + 一行很轻的注解**」：

- 标题 18px，压在一道细线上 —— 像在纸上写一行，是整张卡唯一抢眼的东西；
- 日期 / 预计耗时退成 12px 的淡色小字（`今天 ▾ · 预计耗时 ▾`），不用的时候几乎看不见；
  点开是个小弹层，选完自动收起，点别处或 Esc 也能关；
- **「记下」只在写了东西之后才浮出来** —— 空卡不该摆一个保存按钮在那儿催你。

90% 的情况就是「写一行、回车」，别的一概不打扰。
（演进过程：最早是个裸数字框「— 分钟」；后来改成一行三颗胶囊，但那三颗和标题一样重，
看着就是个表单 —— 所以第三版把它们降级成注解。**表单感来自「所有控件权重相同」**。）

**固定到今日页的事项有标识**：左侧一条主色竖条 + 标题前一个「固定」小标。
不加的话它和普通事项长得一模一样，一眼看不出哪条是被钉住的。

**事项可以带一句「说明 / 补充」**：在「修改」弹框里填，列表里以更小更淡的字显示在标题下面
（和备忘的「补充」同一套语言）。**标签只用来归类和筛选**，别把说明写进标签里 ——
写进去会变成一个方框，读起来像分类而不是注解。

右栏从上到下：

- **备忘**：**贴士，不是待办**。左侧是一朵固定的花标（**不是勾选框**）—— 备忘不需要被「完成」，
  用不上了直接删。每条可以带一句**补充**，字号更小、颜色更淡，是注解而不是第二条内容。
  有时间的按时刻先后排。点一条就地改（改/删都在右边）。
- **睡眠**：昨晚睡了多久，早上打开先看这个。
- **固定**：从日纪/事项固定过来的，日期可点，能就地展开。
- **完成**：今天的完成清单，带时长条。
- **日纪**：只留一个入口和一段摘要；标题、摘要、「今天还没写」的空状态都能点，直接跳到日纪页的今天。

## 周程

侧栏「周程」页：**周末排下周用的**。左边是「待分配」，右边是这一周的 7 天。

- **待分配** = 未完成、且不在这一周里的事项（遗留 + 今天 + 更远的未来）。拖到某一天就排进去了；
  拖不动的话，点一条、再点那天也一样。
- **负荷分析**：每天显示当天已排事项的**预计耗时合计**（已完成且填了实际的，用实际）。
  某天合计 ≥ 2 小时、且 ≥ 有安排的天平均值的 1.5 倍时，标成**偏重** —— 一眼看出哪天排太满。
  两个条件都要满足，而且有安排的天少于 3 天时不标：样本太小的话「平均」没有意义，标出来只是噪音。
- **完成率**：完成 / **全部事项**（完成 + 未完成 + 放弃）。**「放弃」按未完成计** ——
  事情没做完就是没做完，换个说法不该改变这个事实；放弃的件数单独列出来，看得见有几件是自己放下的。
  真正不计入的只有**删除**：删除会把记录从库里物理删掉，自然就不存在了 ——
  也就是说，「不想让它影响完成率」的正确做法是删除，不是放弃。
  一周里没有任何事项时显示「—」，因为「没东西可做」和「一件没完成」是两回事。
- 每条可以点 ✓ 完成、点 × **退回待分配**（放回今天，它就会重新出现在池子里），
  也可以在某天用 ＋ 直接加一件新事。
- **加一件事**（＋ 或右键某天）会弹出一个小表单：标题 + **预计耗时** + **开始时间**。
  只收一个标题太单薄 —— 排期时真正要判断的是「这件事要花多久」，不该先加完再回头改。
- **右键**：在某一**天**上右键 → 直接加一件事到那天；在某一**条**上右键 → 修改 / 标记完成 / 退回待分配。
  「修改」复用今日页那个修改弹框，所以顺手也能改日期（等于把这条挪到别天）。
- **固定的事项不摊进日列**：它不属于任何一周，一直挂在今日页。摊到「创建它的那一天」会误导 ——
  看着像那天要做，其实天天都在。所以单独放在顶上一条虚线带子里（「固定 · N 条」），
  也不进「待分配」池、不参与排期和负荷计算。
- 默认落在**本周**，可以用「上一周 / 下一周」翻。默认值是主进程定的，前端不自己推算日期
  （和 `boot.today` 一个道理）。

**周的定义复用周文件的 ISO 周**（周一开头）。两处必须一致，否则「周程」里看到的周
和落盘的周文件会差一天。周边界与负荷算法都在 `electron/week.cjs`（纯函数，可单独测）。

完成率在三个地方露头：今日页顶栏（今天）、周程页总览（这一周）、回顾页「报告」（整体累计 + 最近 8 周）。
口径只写在 `electron/stats.cjs` 一处，主进程算好百分比下发，前端只负责排版。

## 跑起来

```bash
npm install          # 首次
npm run build        # 构建渲染层到 dist/
npm start            # 启动桌面应用

npm test             # 冒烟 + Markdown 往返 15 项 + 数据层 88 项 + 界面组件 320 项 + 真浏览器 44 项
npm run test:ui      # 只跑界面组件那部分
npm run test:data    # 只跑数据层（真开临时库，逐个跑 bootstrap 依赖的每个 db 函数）
npm run test:browser # 只跑真浏览器布局/交互（需要 Playwright + Chromium，没有就跳过）
npm run seed         # 造一份演示数据到系统临时目录下的 hua-demo/
```

界面测试为什么是 SSR 而不是截图：本机的 Electron 渲染进程经常起不来
（`Failed to create shared context for virtualization`），截图自测不可靠。
`scripts/run-ui-test.mjs` 改用 `vite build --ssr` + `react-dom/server`，
把组件渲染成 HTML 字符串直接断言，几百毫秒出结果、不需要浏览器。
新增展示组件时，在 `scripts/test-ui.jsx` 里补断言。

**但 SSR 只能读 CSS 源码文本、渲染静态 HTML，抓不到「选择器根本没匹配上」这类布局 bug**，
也抓不到交互。所以另外有 `scripts/test-browser.mjs`：起一个 Vite dev server + Playwright(Chromium)，
用**自造的假数据**把页面真的渲染出来，量 `scrollHeight/clientHeight/overflowY`、
`elementFromPoint`，并真的点一遍（分配、勾选、加一条）。
它有 `HUA_BREAK=1` 自检开关：注入修复前的样式后必须出现 FAIL，否则这个测试是假的。

开发模式（热更新）：

```bash
npm run dev                    # 终端 A：Vite dev server (5273)
HUA_DEV=1 npm start            # 终端 B：Electron 指向 dev server
```

环境变量：

| 变量 | 作用 |
|---|---|
| `HUA_DEV=1` | 主窗口加载 dev server 而不是 `dist/` |
| `HUA_DATA_DIR=<路径>` | 换一个数据目录（测试用，不碰真实数据） |
| `HUA_DEBUG=1` | 把渲染层的日志和报错打到终端 |
| `HUA_SHOT=<png路径>` | 截图后退出，用来核对版面 |
| `HUA_SHOT_JS=<js>` | 截图前先执行一段脚本（例如切页签、点按钮） |

## 打包成双击启动的绿色版

不想每次开终端敲 `npm start`？把 Electron 运行时和你的源码一起拷成一个文件夹，**双击 `hua.exe` 就启动**——零安装、零命令行。

```bash
npm run pkg         # vite build + 生成图标 + 打包（约 4 秒）
npm run pkg -- --full   # 强制重拷 Electron 运行时（升级 Electron 后才需要）
```

**打包是增量的**：Electron 运行时（368MB）只要版本没变就不再删也不再拷，只刷新
`resources/app/` 里那几百 KB 的应用源码。所以第二次往后基本是秒完，而且
**应用开着也能打包**（运行时文件不再被碰，不会被占用报错）。

产物在 **`<打包输出目录>\`**（约 369MB，主要是 Electron 自身）：

```
HuaApp/
├── hua.exe                  ← 双击它
├── ...（dll、locales、resources.pak 等 Electron 运行时）
├── resources/app/           ← 你的源码（electron/、dist/、build/、package.json）
└── 使用说明.txt
```

**数据仍然在 `<数据目录>\`**，跟开发跑 `npm start` 是同一份。备份 = 把整个 `<数据目录>\` 目录拷走。

> 💡 重新打包会覆盖 `HuaApp/`——只动应用本身，不动你的数据。

### 想在桌面放个花的图标？

> 当前 AI 工具的沙箱禁止用 COM（WScript.Shell / PowerShell）创建 `.lnk` 快捷方式，
> 所以这里没法自动生成。需要你手动建一个（10 秒）：

1. 在 `<打包输出目录>\` 里**右键 `hua.exe` → 创建快捷方式**。
2. 把生成的快捷方式**拖到桌面**。
3. **右键桌面快捷方式 → 属性 → 更改图标 → 浏览**，选 `<打包输出目录>\resources\app\build\flower.ico`，确定。
4. 改个名（比如「花」）。以后双击桌面图标即可启动。

不想看到控制台窗口的话：右键 `hua.exe` → 属性 → 快捷方式 → 运行方式 = 最小化（窗口本来就用 `autoHideMenuBar`，差别不大）。

## 踩过的坑

**`npx electron .` 有时会把脚本交给 Node 跑。** 本机环境里 `ELECTRON_RUN_AS_NODE=1` 是被注入的，
这个变量会让 Electron 退化成纯 Node，于是 `require('electron')` 返回一个路径字符串，
主进程里 `app` 就是 `undefined`，报 `Cannot read properties of undefined (reading 'disableHardwareAcceleration')`。

```bash
unset ELECTRON_RUN_AS_NODE && npm start
# 或者直接调二进制
./node_modules/electron/dist/electron.exe .
```

**GPU 进程起不来会直接崩掉。** 在远程会话 / 受限桌面 / 老显卡驱动下会刷
`GPU process isn't usable. Goodbye.`。主进程里已经关掉硬件加速并加了一组开关，
纯文字应用不需要 GPU 合成，这是有意的，别删。

**别用 `better-sqlite3`。** 它需要按 Electron 的 ABI 重新编译，而本机没有 MSVC。
用 Node 24 内置的 `node:sqlite`，零编译。

**Markdown 往返必须无损。** 心得存在 Markdown 文件里，编辑器内部是 HTML，
中间的转换一旦有损，写一次再打开内容就悄悄变了。`npm test` 里有 15 项专门测这个——
改 `src/md.js` 之后一定跑一遍。

## 技术选型

| 层 | 选择 | 为什么 |
|---|---|---|
| 外壳 | Electron 44 | 本机没有 Rust/MSVC，Tauri 要补 5–8GB 工具链；自用工具不在意 150MB 体积 |
| 前端 | React 19 + Vite 8 | 两栏联动、周月切换、检索高亮，状态复杂度已经超出无框架写法 |
| 编辑器 | TipTap 3 | 富文本，但落盘是 Markdown |
| 存储 | `node:sqlite`（Node 24 内置） | **不需要本地编译**，绕开 better-sqlite3 的 ABI 问题 |
| 心得 | Markdown 文件 | 十年后还能用记事本打开 |

## 数据在哪

默认落在**非系统盘**（`<数据目录>`），C 盘紧张时不占系统盘；都没有才退回「文档/Hua」。

```
Hua/
├── data.db              # 事项 + 心得检索索引（SQLite）
├── journal/             # 心得，一周一个 Markdown 文件
│   └── 2026-W38.md
└── reports/             # 周报月报
    ├── week-2026-09-14.md
    └── month-2026-08.md
```

**备份就是整个目录拷走。**

周文件长这样（一天可以有多条心得，标题和置顶都写在小标题里）：

```markdown
# 2026 年第 38 周（09-14 ~ 09-20）

## 09-18 周五

### 完成
```

格式要点：

| 写法 | 含义 |
|---|---|
| `#### HH:MM` | 一条心得，时间即它的身份（同一天不能重复） |
| `#### HH:MM · 标题` | 带标题。折叠时显示标题，没标题才退回首行预览 |
| `#### HH:MM · 标题 ·置顶` | 固定到今日页。置顶永远是最后一段 |
| `### 心得 · 标题 ·置顶` | 旧版「一天一篇」留下的无时间条目，没有 `####` 可挂，记在小节上 |

「置顶」也写进文件，不另开状态文件——哪条被固定，用记事本打开周文件一眼能看懂。

## 几条不显然的规则

这些都是刻意的，别"顺手改回来"：

1. **完成清单是快照，不是镜像。** 次日首次打开时写入周文件，之后不再回改。改个事项标题不会重写历史文件。→ ADR-0005
2. **未完成的事项不自动顺延。** 它们留在原日期，今天页顶部提示还剩多少，你手动拉。→ ADR-0008
3. **不设分类，也不设项目，只用标签。** 你的工作是零散日常，分类会逼出「其他」垃圾桶，项目会腐烂。→ ADR-0007
4. **不做 AI 总结。** 周报月报是机械汇总。回顾的价值在于重读自己写的原话。→ ADR-0006
5. **心得按周一个文件，不按天。** 十年 520 个文件，而不是 3650 个。→ ADR-0004
6. **日界默认 04:00。** 凌晨 4 点前写的记录算前一天。这条规则只在
   `electron/day.cjs`（纯函数，可单独测），主进程通过 `boot.today` 下发给各页面。
   **前端一律不要自己 `new Date()` 取当天** —— 凌晨 1 点写日志，本该落在「还没睡的那一天」，
   自己算就会错到新的一天去（踩过：日志页曾这样，把日记劈成两半）。
   可在设置里改。
7. **空心得也会落盘。** 点「+ 新增一条」时正文是空的，序列化时不能按「正文非空」过滤，
   否则新条目刚建就被丢掉（踩过：界面上表现为「点了没反应」）。
8. **切页签要重新拉 bootstrap。** 否则在回顾里改的东西回不到今日页。
9. **未来日程内联在今日页，不另开「计划」页。** 今日页左栏有个「接下来」区块（默认收起，
   标题带「明天 2 · 后天 1」的分布摘要），只往前看 7 天，更远的只给一行计数。
   输入框上可以切「今天 / 明天 / 后天 / 具体日期」，排到未来的事到了那天自然进今日列表，
   没做完第二天再进「遗留」—— 全程不需要搬运，与 ADR-0008 一致。
   不做独立计划页是因为：过去一页、未来一页会让「今天」降格，而这个应用的重心就是今天。
   **2026-10-16 补：「周程」是这条规则唯一且刻意的例外。** 它不是「计划页」的复活 ——
   它一周只用一次（周末排下周），平时不需要看，定位是「排下周」这个**动作**而不是每天的计划台。
   所以它排在「回顾」后面（回顾完顺手排下周），今日页的「接下来」区块原样保留、没有被取代。
   （2026-10-19：默认落在**本周**而不是下周 —— 打开先看这一周排得怎么样，要看下周点一下「下一周」。）
10. **遗留区块默认收起，只留入口。** 打开应用第一眼应该是「今天」，不是前几天没做完的事。
    入口上带件数角标，收着也知道还剩几件（`showBacklog` 初始为 `false`）。
11. **心得与日志是同一份数据，两种视图。** 日志页按天聚合、一天一篇；回顾页按天折叠看
    原始条目。不要为「日志」另存一份文件——磁盘上始终只有周文件里的 reflections。
